# 个人规划仪表盘

这是给 Obsidian 用的原生规划仪表盘插件：Markdown + YAML frontmatter 是唯一事实来源，
界面只读取、展示与跳转，所有写操作都由你显式触发。

## 项目介绍 

**Nekofi Dashboard** 旨在帮助个人集中管理长期目标、阶段性任务、个人项目视觉化跟进及日常规划。通过直观的数据可视化与模块化看板，告别碎片化的待办工具，提供一站式时间与精力管理解决方案。

### 核心亮点
#### **循环学习架构**：让知识可以复用
以"项目驱动学习，学习辅助项目"的循环架构进行知识库复用化，避免"不知道学什么"、"学完就吃灰"的痛点。

### 项目内容

#### 层级
| 层 | 住在哪 | 关键字段 |
| --- | --- | --- |
| 草稿（入口层） | `00 草稿箱/` | `stage: inbox` —— 任何想法先落这里 |
| 项目（决策层） | `20 项目库/<项目名>/<项目名>.md` | `outcome`（要什么结果）、`acceptance`（怎么算成）、`deadline`、`milestones`（关键节点） |
| 任务（执行层） | `50 日程待办/`，或所属项目文件夹内 | `due`（DDL）、`duration`（预计分钟）、`status`、`task_set` / `task_group`、`project`、`milestone` |
| 知识（沉淀层） | `30 知识库/`、`40 人物库/`、`10 长期领域/` | `知识库`为笔记中心，`人物库`和`长期领域`待更新 |
| 归档（收尾层） | `90 归档库/` | 归档已完成的任务和项目，可撤销 |

#### 六大板块
| 板块 | 怎么打开 | 它解决什么问题 | 主要操作 |
| --- | --- | --- | --- |
| **仪表盘（Web 版）**（默认入口） | 命令 `打开个人规划仪表盘（Web 版）` | 每天第一眼该看哪：今天做什么、哪里超载、哪里欠账 | 顶部 `概览 / 任务 / 项目 / 知识 / 草稿箱 / 数据` 六个页签；任务行内就能「标记完成」「完成并归档」；点标题开右侧详情抽屉 |
| **个人规划仪表盘**（经典原生视图） | 命令 `打开经典视图（排错用）` | 与 Web 版同一份数据，但用 Obsidian 原生控件渲染（排错、对照用） | 头图横幅 + 4 张统计卡（进行中项目 / 未来 N 天任务 / 逾期任务 / 草稿箱）+ 今日焦点 + 项目推演 + 时间监控 + 今日任务监控 + 知识缺口 |
| **日程待办** | 仪表盘「任务执行」卡，或左侧栏 | 把任务按「任务集 → 任务组 → 任务」铺开 | 搜索、按任务集/任务组/状态/优先级筛选与排序；标记完成、重开、归档、编辑、删除；勾选多条批量改状态或挂到同一项目与节点 |
| **单项目页面** | 点任意项目名 | 一个项目推进到哪了 | 关键节点导航（页签）、任务追踪、阻塞项与阻塞原因、孤立任务、完成度 |
| **草稿箱** | 仪表盘「分诊 / 整理」卡，或命令 `处理草稿箱` | 新想法先接住，之后再决定去向 | 分诊（转任务 / 转知识 / 关联引用 / 删除）、`周维护：导入草稿为任务集` |
| **规划资源** | 仪表盘「知识沉淀」「个人方向」卡 | 学习与长期方向 | 按「知识笔记 / 图书 / 视频 / 人物库 / 关于我」分组浏览，显示每篇关联了几个项目 |

## 安装方法
下载此库，将库解压后放入目录：Obsidian库\.obsidian\plugins中，重新打开Obsidian即可在设置中启用
更新库时将新库文件夹覆盖旧版本文件夹，数据层为对Obsidian七个受管目录的监测，不会被覆盖

## 使用方法
### 首次使用
1. 打开它：Ctrl/Cmd + P → 「打开个人规划仪表盘（Web 版）」。
2. 看引导卡：整库没有项目也没有任务时，Web 面板顶部会出现「开始使用 / 这个仪表盘没有自己的数据，它只读你 vault 里的 Markdown」，带三个按钮：初始化目录结构、新建项目、先看看整库有哪些笔记（app.js:1219-1230）。原生视图（排错用）也有同样的卡片（dashboard.ts:47-52）。
3. 决定目录对应关系：接受默认的中文目录名，或者先在设置里把 8 个目录改成自己库里的名字。⚠️ 顺序不能反 —— 「初始化」建的是当前设置值。
4. 点「初始化目录结构」（设置页里或引导卡上）：只创建不存在的目录，不删不改已有内容。它建 8 个：00 草稿箱 10 长期领域 30 知识库 30 知识库/图书库 40 人物库 20 项目库 50 日程待办 90 归档库。图片素材 不在其中，它在你第一次选横幅图时才按需创建。
5. 用插件的「新建项目 / 新建任务」建第一条 —— 这是最省事的做法，因为它会写对 frontmatter 字段（项目写 type: project / title / status / outcome / acceptance / deadline / milestones 等）。

#### 已有笔记的库：两种迁移策略
| 策略 | 做法 | 代价 |
| --- | --- | --- |
| **让插件适配你的库**（推荐） | 在设置里把 7 个受管目录改指到你现有的目录 | 目标目录不存在时不会替你建，等你点「初始化」 |
| **让你的库适配插件** | 接受默认的中文目录名，把笔记挪进去 | 要搬文件，但所有文档与截图都对得上 |

> ⚠️ **顺序不能反**：「初始化目录结构」创建的是**当前设置值**。先改目录名、再点初始化；反过来会先建出一批默认目录。

### 日常使用

#### 早晨 5 分钟：决定今天

1. 打开仪表盘 → `概览`：先看 **今日焦点**（最该推进的一件事）与 **今日任务监控**
   （今天到期的任务与总耗时；超过「每日可用时间」会标成**超载**）。
2. 需要调整就直接在 `任务` 页签动手：改 DDL、优先级、耗时，或点标题开详情抽屉改任意字段。
3. 心里有数了就开始做 —— 做完点行内「标记完成」。

#### 白天：随手记 → 分诊 → 执行

- **随手记**：想到什么先扔进 `00 草稿箱/`（或直接写一条笔记），不用当场决定归属。
- **分诊**：运行 `处理草稿箱`，一条条决定它是任务、知识、引用，还是删掉；
  一周攒下的一批可以用 `周维护：导入草稿为任务集` 一次性转成任务集 + 任务组。
- **执行**：任务行「标记完成」；确定不再需要这条笔记时用「完成并归档」，文件会被搬进 `90 归档库`。

#### 周末 15 分钟：周维护

1. 草稿箱清空一轮（周维护导入 / 分诊）。
2. 仪表盘看 `项目推演`：哪个项目该往前推、哪个关键节点卡住了（阻塞项会单独列出）。
3. 归档已完成 / 已废弃的任务；需要时用 `撤销当前任务归档` 找回。
4. 有重复任务的话，检查 `重复周期`（每周几 / 每月几号 / 重复到哪天为止）。

### 设置项

| 设置 | 默认值 | 必需 | 影响 |
| --- | --- | --- | --- |
| 00 草稿箱 | `00 草稿箱` | ✅ | 分诊入口、草稿箱提醒 |
| 10 长期领域 | `10 长期领域` | ✅ | 长期领域页签、项目 `area` 下拉 |
| 20 项目库 | `20 项目库` | ✅ | 项目与项目任务 |
| 30 知识库 | `30 知识库` | ✅ | 知识页签、知识缺口沉淀 |
| 图书库 | `30 知识库/图书库` | 建议 | 图书归档；改知识库而它仍是默认值时会自动跟着走 |
| 40 人物库 | `40 人物库` | 建议 | 执行者下拉、人物页签 |
| 50 日程待办 | `50 日程待办` | ✅ | 无项目任务、任务页签 |
| 90 归档库 | `90 归档库` | ✅ | 归档目标与撤销归档（不扫描） |
| 图片素材 | `图片素材` | 可选 | 横幅素材来源；选图时按需创建 |
| 每日可用时间 | `120` 分钟 | 建议改 | 时间规划的超载判断 |
| 时间监控范围 | `7` 天 | 建议改 | 「未来 N 天任务」的窗口 |
| 默认任务时长 | `30` 分钟 | 可选 | 新建任务的默认 `duration` |
| 启用规划提醒 | 开 | 可选 | 到期通知，每天最多一次 |
| 提醒时间 | `9` 时 | 可选 | 24 小时制整点 |
| 仪表盘横幅 | 未选 | 可选 | 从「图片素材」挑，或直接从电脑选图并取景 |
| 界面动效 | `完整` | 可选 | 完整 / 克制 / 关闭；系统「减少动效」始终优先 |

### 配置体检
设置页最上方会把目录问题摆出来，每条都带一个能直接点掉的修复按钮：

- **目录不存在** → 「创建这些目录」（检查草稿箱 / 项目库 / 日程待办 / 归档库 / 知识库 / 长期领域 / 人物库 共 7 个）
- **两个目录配成了同一路径**（同一篇笔记会同时被算作草稿和任务）→ 「恢复默认值」
- **目录互相嵌套**（如任务库放在草稿箱里）→ 「恢复默认值」
